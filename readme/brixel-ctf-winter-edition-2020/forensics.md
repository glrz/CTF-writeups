## Lost evidence

Note: This challenge was not solved during the competition. I solved it after the competition.

![](<../../.gitbook/assets/image (216).png>)

For this challenge, we are given a zip file. Inside the zip file, there is a .img file

{% file src="../../.gitbook/assets/evidence.zip" %}

The challenge description mentioned something about deleted pendrive containing crucial evidence. Perhaps we could use Autopsy for this. Autopsy is basically a digital forensics tool and can be used to recover deleted items.

I downloaded [Autopsy ](https://www.autopsy.com/)on Windows OS, you can use it on Linux too if you prefer.

Opening up Autopsy, we first select a new case

![](<../../.gitbook/assets/image (80).png>)

Then, we will give it a Case Name. Actually any name will do, for me I just put `1`

![](<../../.gitbook/assets/image (238).png>)

Next, it will prompt you to provide more information. We can just press finish.

![Note: This step is optional](<../../.gitbook/assets/image (265).png>)

Click `Next >`

![](<../../.gitbook/assets/image (73).png>)

Click `Next >` again since we are selecting a disk image

![](<../../.gitbook/assets/image (56).png>)

Browse to the `evidence` file path and click `Next >`

![Selected evidence.img ](<../../.gitbook/assets/image (242).png>)

Here, we can continue to click `Next >`

![](<../../.gitbook/assets/image (134).png>)

After that, it will add and process the data. This process could take a minute or two. Finally, we can click `finish`.

![Data source added to database](<../../.gitbook/assets/image (35).png>)

On the left, we could go to the `Deleted Files` section and expand it.

We could see 2 .wav files being deleted

![](<../../.gitbook/assets/image (195).png>)

We can press CTRL+A to select all the items and then right click to extract files

&#x20;

![](<../../.gitbook/assets/image (194).png>)

Select the destination to extract to and after that's done, a successful extract message will pop up.

![](<../../.gitbook/assets/image (250).png>)

After hearing both audios, I determined that both audios are the same.&#x20;

If we listen to the recording, it plays an audio of the tones generated by a telephone when the numbers are pressed. At the end, around 1:05 mark of the audio, he adds a 'personal message' to. We can 'decode' these tones as they are known as DTMF signals.

First, we analyze the audio in Audacity.

I will now copy the portion from 1:05 onwards till the end of the audio.

![Notice the highlighted part - Drag and hold the mouse then right click and copy](<../../.gitbook/assets/image (28).png>)

Now, I will paste the copied audio portion into a new file in Audacity.

![Audio containing the 'personal message'](<../../.gitbook/assets/image (17).png>)

Extract this audio to a .wav file

![](<../../.gitbook/assets/image (77).png>)

Here we can edit metadata information but we don't need to, so we can press ok

![](<../../.gitbook/assets/image (3).png>)

At this point, there are several ways we could apply to decode this DTMF tone.

We could use an online tool [here](http://dialabc.com/sound/detect/index.html) or use a DTMF decoder that can be downloaded on Linux [here](https://github.com/ribt/dtmf-decoder).

Using the online tool, we decoded the DTMF tones

![](<../../.gitbook/assets/image (78).png>)

We can read the numbers on the left vertically and we will get the decoded output : 8449903336667770844330222666222244466330227778844

Now, for the final step we can decode the message [here](https://www.dcode.fr/multitap-abc-cipher).

![](<../../.gitbook/assets/image (26).png>)

We get: THX FOR THE COCAINE BRUH/BRUGG

Now we know the suspect bought cocaine.
